# 収益化ロードマップ

更新日: 2026-09-10

## プロダクトの軸

「億り人を目指す配達員を応援する」。毎日の売上・経費・稼働を記録し、収益の振り返り、実際の純資産に基づく目標進捗、車両ごとの整備履歴を一つのアプリで扱う。資産形成の成果を保証する表現は使わず、売上の累計を純資産として表示しない。

当面は自分自身の Excel への二重入力をなくすことを優先する。車両別整備履歴とカード中心の UI を実装し、次に日別明細・月次集計の Excel／CSV 出力を検討する。少人数の配達員に入力時間と継続利用を確認してから、新たな省力化機能の課金を検証する。

## 推奨方針

最初からApp Store向けに作り直さず、現在のPWAで需要を検証し、認証・クラウド同期・課金が定着してからCapacitorでiOS／Androidアプリ化する。現在のHTML、CSS、JavaScriptを生かせるため、機能検証を速く進められる。

## 段階1: 非公開ベータ

- Vercel Web Analyticsで利用端末、継続利用、主要画面への到達を測る。
- 5〜20人の配達員に招待制で使ってもらう。
- 入力時間、月次集計、確定申告見込みのどれに最も価値があるか確認する。
- 税額が概算であること、データの保存先、プライバシー方針を明示する。

## 段階2: アカウントとクラウド同期

Supabase Authとクラウド同期は2026-09に実装済み（[運用ガイド](operations.md)の「クラウド同期」を参照）。現時点では全利用者へ無料で提供し、課金は入れていない。残りは有料化の設計。

- ~~Supabase AuthとPostgresを導入する。~~ 実装済み。マジックリンク認証＋`app_private` スキーマ＋RLS。
- ~~PC・スマートフォン間の同期、自動バックアップ、機種変更対応~~ 実装済み。これらを有料価値の中心に据えるかは、利用状況を見てから決める。
- 無料と有料の線引きを決める前に、同期の実利用率と継続率を測る。
- 無料版は端末内保存と基本集計、有料版はクラウド同期、複数車両、高度分析、CSV／確定申告向け出力を候補にする。
- Stripe等で月額・年額プランを提供する。価格は利用者インタビューと継続率を見て決める。

## 段階3: アプリストア展開

- PWAの継続利用と課金が確認できたらCapacitorでiOS／Androidを包む。
- 通知、レシート撮影、位置情報を使う機能だけをネイティブ連携する。
- ストア審査、アプリ内課金、プライバシー表示、税務表現の審査コストを見込む。

## 収益源の候補

- 個人向けサブスクリプション: クラウド同期、自動バックアップ、高度分析、税務出力。
- 年額プラン: 月額より割安にして解約率を抑える。
- 紹介提携: 車両保険、会計ソフト、整備、通信サービス。利用者利益と広告表記を優先する。
- 法人向け: 配達チームの稼働・経費集計。個人版で需要を確認した後に分離する。
