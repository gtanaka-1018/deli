# 振込金額の記録と集計

更新日: 2026-09-07

## 記録の意味

振込金額は、プラットフォームから実際に振り込まれた金額を記録する。振込日は日別記録の `date` とする。同日に複数のプラットフォームから入金があった場合や、同じプラットフォームから複数回入金があった場合は、振込をそれぞれ追加する。

振込額は売上とは別に集計する。売上・利益・税額の計算へ加算せず、純資産の残高も自動では変更しない。売上とその振込を二重に収入へ計上しないためである。振込日の集計なので、その期間に稼いだ売上と振込額が一致するとは限らない。

## データ形式と互換性

保存形式は `schemaVersion: 3` とし、既存の `records[日付]` に `payouts` 配列を追加する。既存の売上・経費フィールドは引き続き利用する。

```json
{
  "date": "2026-09-07",
  "payouts": [
    { "id": "payout-example-1", "providerId": "uber", "amount": 1000, "memo": "" }
  ]
}
```

上記は架空の形式例である。`providerId` はプラットフォームの ID、空文字は「未分類」を表す。プラットフォームを非表示にしても、既存の振込の集計対象からは外さない。`amount` は有限かつ正の数のみを採用する。`id` が欠けた入力や重複 ID には決定的な ID を補い、読込のたびに ID が変わらないようにする。

旧形式の `sourceData.transferAmount` は、`payouts` フィールドがない場合に限り、ID `legacy-transfer` の未分類の振込として読み込む。旧形式の有効な金額は丸めずに保持する。`sourceData` の元の値は残しても二重加算しない。`payouts: []` は明示的に振込がない状態として扱うため、削除した旧形式の振込が次の読込で復活することはない。不正な `payouts` フィールドも旧形式へのフォールバックには使わない。

`public/payout-data.js` の `normalize(record)` が日別の振込を正規化し、`summarize(records)` が振込合計・件数・プラットフォーム別合計・日付降順の明細を返す。日・週・月・年の対象日付の選択は呼び出し側で行う。集計は対象期間内の振込日を基準にする。

## 保存・バックアップ・ロールバック

正本は引き続き端末ごとの `localStorage` に置く。振込は日別記録の一部なので、JSON エクスポート／インポート、端末内の控え・復元ポイント、任意で有効にしたクラウド同期のスナップショットに既存の記録と一緒に含まれる。クラウド同期は既定で停止しており、この機能で有効にはならない。

旧形式のバックアップも読み込める。振込を含む記録を編集するときは、`schemaVersion: 3` に対応した版を使用する。古い版は新しい `payouts` を表示・集計できず、日別記録の正規化・編集保存によって追加フィールドを失う可能性がある。

旧版へ戻す前に、設定から全データの JSON バックアップを書き出して保管する。旧版では振込記録の編集を避ける。再び対応版へ戻したら、必要に応じて退避したバックアップを読み込み、振込の件数と合計を確認する。クラウド同期を利用している場合は、旧版の編集で対応版の記録を上書きしないよう、ロールバック中は同期を停止する。
