# 車両ごとの整備履歴

更新日: 2026-09-10

## 記録と保存

「整備」画面で登録済みの車両を選び、日付・積算走行距離（任意）・整備内容・メモ（任意）を記録する。車両ごとの履歴を新しい順に表示し、編集・削除できる。車両の表示名を変更しても ID で履歴を関連付け、非表示にした車両も履歴の対象から外さない。

整備履歴は作業の記録であり、売上・経費・税額・資産残高を変更しない。費用の記録は従来の経費入力を利用する。

保存形式は `schemaVersion: 4`。既存の保存オブジェクトのトップレベルに `maintenance` 配列を追加する。各要素は `id`、`vehicleId`、`date`、`odometerKm`（不明は `null`）、`description`、`memo` を持つ。実データを公開ファイルへ埋め込まない。

正本は端末ごとの `localStorage`。JSON 書き出し・読み込み、端末内の控え・復元ポイント、利用者が有効にしたクラウド同期に含める。同期は引き続き既定で停止する。整備履歴だけを持つ端末も別アカウントへの送信防止と復元ポイント作成の対象とする。

## 互換性とロールバック

バージョン 3 以前のファイルなど `maintenance` がないスナップショットを読み込む場合は、現在の整備履歴と、その履歴に必要な既存車両を保持する。`maintenance: []` は明示的な空の履歴として扱う。バージョン 4 の復元・同期では、そのスナップショットの履歴を適用する。

旧版は整備履歴を理解せず、保存・同期すると追加フィールドが失われる可能性がある。旧版へ戻す前にバージョン 4 の全データを JSON で退避し、ロールバック中は同期を停止する。対応版へ戻したら退避したファイルを読み込み、車両ごとの件数・日付・内容を確認する。旧版との同時編集は避ける。

この変更はサーバー側のテーブルや認可を変更しない。既存の利用者別スナップショットと RLS を利用する。

## 整備履歴だけの取り込み

整備画面の「履歴を取り込む」から専用JSONを読み込み、追加先の既存車両または新規車両を選ぶ。全件を確認して「履歴を追加する」で確定する。日々の記録・経費・資産を置き換えない。設定画面の全体バックアップ読み込みとは別の操作である。

形式は `type: "okumeter-maintenance"`、`version: 1`、`vehicle: { label, type }`、`entries: [{ id, date, odometerKm, description, memo }]`。日付は実在するISO日付、距離は非負の数値またはnull。2MB・2000件以内とし、不正な行が1件でもあれば全体を拒否する。実データのファイルは `data/` または利用者の端末にのみ置き、Git・Vercelへ含めない。

取り込み元IDは変更しない。車両ごとの取り込み元IDが同じ履歴は再追加せず、手入力済みの同一日付・距離・内容も重複として扱う。すでに編集した履歴は上書きしない。別車両への取り込みは独立して扱う。

追加前の全体を復元ポイントへ保存する。保存できない場合や、その間に同期で車両・整備履歴が変わった場合は追加を中止する。追加の保存が失敗した場合は車両と履歴を元に戻し、取り込み画面の内容を残す。取り消す場合は設定画面の「整備履歴の取り込み直前」へ復元できる（復元は記録全体を戻すため、以後の入力がある場合は先に書き出す）。保存形式はバージョン4のまま。元のExcelの記載に不整合があれば、補正の根拠または未確認の原文を各履歴のメモに残す。
