# 売上分析

更新日: 2026-09-15

## 目的と表示場所

「集計」の主要指標の下に「売上分析」を表示する。日・週・月・年と期間選択に連動し、売上増減の内訳と曜日・プラットフォーム・天気別の実績を確認できる。

端末の既存レコードから都度計算する。保存形式の変更、外部への分析データ送信、クラウド同期の有効化は行わない。振込金額は売上に足さず、振込だけの日は稼働日数にも含めない。

## 比較期間

- 日: 前日。週: 月曜始まりの前週。月: 前月。年: 前年。
- 今週・今月・今年の途中では当日までを対象とし、前週は同じ曜日、前月・前年は対応する日付までを比較する。存在しない日付は月末に揃える。
- 終了した期間は期間全体で比較する。月の日数や曜日構成は異なるため、売上総額に加えて稼働日数・時間も確認する。
- 未来の期間は分析しない。両期間に売上・件数・稼働時間のいずれかの記録がない場合、増減率や内訳は算出しない。前期間の売上がゼロの場合も増減率は表示しない。
- 記録がない日を休日や売上ゼロと断定しない。

## 計算方法

### 売上の増減

平均単価 = 売上 / 件数。件数と単価の両方が変わった際の交差分を半分ずつ配分する。

```
件数による増減 = (今回件数 - 前回件数) × (今回単価 + 前回単価) / 2
単価による増減 = (今回単価 - 前回単価) × (今回件数 + 前回件数) / 2
```

両者の和は売上差額と一致する（円表示の丸めで差が出る場合がある）。これは数値上の分解であり、需要や天気などの因果関係を示すものではない。

売上が正で件数がゼロのサービスが1つでもある場合、件数未記録や件数を伴わないボーナスを区別できないため、その期間の平均単価と増減の分解を表示しない。会社別単価も同様。

### 時給と母数

- 時給 = **時間を記録した日の売上合計 / 同じ日の稼働時間合計**。売上だけの日は分子・分母とも対象外。
- 稼働時間は既存の手動上書き、稼働区間、休憩控除、旧形式の時間をアプリと同じ優先順で扱う。
- 「経費差引後の時給」は、時間記録日の売上から同じ日の記録済み経費を引いて計算。別日に記録した経費、税金等を含む可処分所得ではない。
- 曜日の中央値は時間記録日の各日時給の中央値。全体時給の平均とは区別する。
- 「1日平均売上」は売上・件数・時間のいずれかの記録がある日の平均。経費のみ・振込のみの日を除く。
- 各曜日に時間記録3日以上かつ合計6時間以上あることを比較の最低条件とする。条件を満たす曜日が2つ以上あり、最高時給が同率でない場合のみ記録上高めの曜日を表示する。この条件は統計的有意差を保証しない。
- 曜日・天気の表には時間記録日数／稼働日数と時間を併記する。時間がない場合は「—」、記録時間があり売上ゼロの場合は0円。

プラットフォーム別の稼働時間は記録していないため、会社別時給は算出しない。売上・構成比・件数・単価・前期間の売上差を表示する。天気と売上の関係も記録上の比較であり、天気が原因とは断定しない。

### 時間帯別の既存表示

時間帯別は稼働時間の配分を示す。1日の売上・件数を稼働分数で按分した推定値を併記するが、時間帯別の実売上ではない。按分時給から「稼げる時間帯」を推薦する表示を廃止し、棒の長さを稼働時間に変更した。

## 他ツールを踏まえた優先順位

2026-09-15に各公式サイトを確認。

- [Gridwise](https://gridwise.io/features): 複数アプリの収益追跡、稼働効率、地域・曜日・会社の比較等を案内。
- [INTWAK Delivery Pro](https://internetwak.com/lp/intwak-delivery-pro): プラットフォーム・曜日・天気別分析や目標管理を案内。
- [フードデリバリー売上管理](https://fd-result.com/): 複数サービス、売上・経費、時間・曜日の分析等を案内。

比較軸を増やすだけでなく、「なぜ増減したか」と「記録がどこまで揃っているか」を一緒に読めることを今回の改善方針とした。他ツールに同等機能がないことや、効果で上回ったことを示す調査ではない。

次の候補は、入力の負担を確認したうえでの稼働区間別売上の記録、区間別の実績比較、目標達成に必要な稼働のシミュレーション。現在の按分値だけで時間帯や会社を自動推薦しない。
